# i18n application guide

MSYS i18n is deliberately an application-local file plus a tiny lookup API.
There is no global daemon, D-Bus API, framework lock-in, or package-manager
dependency. The normative format and fallback rules live in
`msys-contracts/specs/i18n.md`; this page is the practical SDK workflow.

## Add a catalog

Copy one of the `msys-contracts/examples/i18n` catalogs into the application:

```text
my-package/
├── manifest.json
└── files/
    ├── app/
    └── share/i18n/catalog.json
```

A minimal file is:

```json
{
  "$schema": "https://msys.local/schemas/i18n-catalog.v1.json",
  "schema": "msys.i18n.catalog.v1",
  "id": "org.example.my-app",
  "default_locale": "en-US",
  "messages": {
    "en-US": {
      "app.title": "My app",
      "welcome": "Welcome, {name}"
    },
    "zh-CN": {
      "app.title": "我的应用",
      "welcome": "欢迎，{name}"
    }
  }
}
```

The default locale is the complete key inventory. A translation may omit a key
and inherit the default but may not invent one. This catches typos while still
allowing translation work to land incrementally.

Validate before building the package, with no Python dependency beyond the
standard library:

```sh
cd msys-contracts
python3 -m tools.i18n_tool validate \
  ../my-package/files/share/i18n/catalog.json
```

No manifest role, interface, permission, lifecycle field, or installer hook is
needed. The catalog is an ordinary immutable package resource.

To localize the name and summary shown by compatible launchers, add the
optional presentation-only extension to the package or component:

```json
"x-msys-i18n": {
  "catalog": "files/share/i18n/catalog.json",
  "name_key": "app.name",
  "summary_key": "app.summary"
}
```

Keep ordinary English `name` and `summary` fields as recovery copy. The
extension grants no permission and does not affect whether a component is
launchable.

## Python API

```python
from msys_sdk import CatalogError, Translator

try:
    i18n = Translator.from_file("files/share/i18n/catalog.json")
except CatalogError as error:
    # A packaging/development error: error.issues contains all detected faults.
    raise SystemExit(str(error))

title = i18n.text("app.title")
welcome = i18n.text("welcome", {"name": "Ada"})
optional = i18n.text("feature.label", fallback="Feature")
```

Integer plurals remain ordinary v1 strings instead of introducing an ICU
runtime or a second resource format. Add suffixed keys to the complete default
locale and only the forms needed by each overlay:

```json
"en-US": {
  "files.one": "One file",
  "files.other": "{count} files"
},
"zh-CN": {
  "files.other": "{count} 个文件"
}
```

Then use the same translator:

```python
label = i18n.plural("files", file_count)
```

Resolution is locale-first: each selected/parent/default locale computes its
own category, then tries that form and its `.other`. This keeps fallback text
grammatical when the requested language and fallback language have different
rules. An old unsuffixed key is accepted last for compatibility. `count` is injected safely without
mutating the caller's parameters. The compact integer rules cover the common
one/other languages plus Chinese/Japanese/Korean, Arabic, Slavic, Baltic,
Romanian, Hebrew, Welsh, and Irish categories. This is a cardinal integer API,
not a replacement for application-formatted dates, decimals, or ordinals.

When no explicit locale is passed, the constructor samples `MSYS_LOCALE`,
`LC_ALL`, `LC_MESSAGES`, and `LANG` in that order. `zh_CN.UTF-8` is normalized
to `zh-CN`. `C`, `C.UTF-8`, and `POSIX` choose the catalog default.

An application-owned language selector can switch immediately without changing
global process locale state:

```python
i18n.set_locale("en-US")
rebuild_visible_labels()
```

`i18n.locale`, `i18n.resolved_locale`, and `i18n.fallback_chain` expose the
decision for a developer panel. Recoverable problems are retained in a bounded
`i18n.diagnostics` tuple and may also go to a callback:

```python
def report(problem):
    print(problem.as_dict())

i18n = Translator.from_file(
    "files/share/i18n/catalog.json",
    on_diagnostic=report,
    diagnostic_limit=64,
)
```

A failing diagnostic callback is ignored so a logging fault cannot turn a
missing optional label into an application crash. Set `diagnostic_limit=0` to
disable retention. Catalog validation failures remain exceptions because they
are broken package content, not an expected runtime fallback.

Only strings and non-boolean integers in JavaScript's exactly representable
`-9007199254740991..9007199254740991` range are valid placeholder values.
Preformat dates, floats, larger integers, units, and localized numbers in
application code and pass the display-ready string. Missing/invalid values
remain visible as `{name}` and produce a diagnostic. Extra values are ignored.

## Qt/C++, Electron, and C

The JSON contract is the API boundary; using the Python SDK is optional.

For Qt/C++, open the same path with `QFile`, parse it with
`QJsonDocument::fromJson`, and retain the `messages` object. Normalize the
requested locale, construct its parent chain, select the first map containing
the key, then run a single-pass brace renderer. Do not call `QString::arg` on
translator-controlled text because numbered replacement has different
semantics. A small application helper can return `QString` and notify widgets
when its explicit locale changes.

For Electron/Node, loading is equally direct:

```javascript
const fs = require("node:fs");
const catalog = JSON.parse(
  fs.readFileSync("files/share/i18n/catalog.json", "utf8")
);
```

Use `catalog.default_locale` and `catalog.messages[locale]` with the exact
fallback algorithm in `msys-contracts/specs/i18n.md`. Implement replacement as
a scanner for `{name}`, `{{`, and `}}`; do not use JavaScript template
evaluation or a general expression library. Package validation is important
because `JSON.parse` by itself does not report duplicate object keys.

For C/C++, MSYS does not force a JSON library into the target image. Generate a
static UTF-8 header during the workstation/build step:

```sh
PYTHONPATH=/path/to/msys-sdk python3 -m msys_sdk.i18n_c \
  files/share/i18n/catalog.json build/app_catalog.h \
  --symbol app_catalog
```

The generated header includes `<msys/i18n.h>` and defines `app_catalog`.
Lookup, plural selection, and interpolation are dependency-free and allocate
no heap memory:

```c
#include <msys/i18n.h>
#include "app_catalog.h"

char locale[MSYS_I18N_LOCALE_CAPACITY];
char label[96];
msys_i18n_param values[] = {{"count", "3"}};

if (msys_i18n_locale_from_environment(locale, sizeof(locale)) != MSYS_I18N_OK)
    locale[0] = '\0'; /* lookup uses catalog default */
const char *message = msys_i18n_lookup_plural(&app_catalog, locale, "files", 3);
msys_i18n_render(message, values, 1, label, sizeof(label), 0);
```

`msys_i18n_locale_from_environment()` uses the same `MSYS_LOCALE`, `LC_ALL`,
`LC_MESSAGES`, `LANG` precedence. Applications that already bundle a JSON
parser may still load the source directly; the static header is simply the
small-target path. The mIPC and i18n functions share the existing static SDK
archive but remain independent APIs.

## Recommended developer boundary

Keep one `Translator` (or equivalent helper) per catalog, and keep visible
source strings out of widget construction code. Pass stable keys to that helper
at the point labels are built. Framework-specific concerns such as widget
refresh, font selection, right-to-left layout, or virtual-keyboard composition
remain UI responsibilities; they are intentionally not coupled to message
lookup.

Do not combine catalogs by unqualified message key or install order. Each
catalog id owns its own namespace. Shared system wording should live in an
explicit shared catalog that the application deliberately loads, rather than a
hidden global merge.
